1. Folder model: a Backup folder of Kind=Photos (exists, Backup-only). Per device, instead of a local path: a media selection on FolderDevice — all photos and videos, or chosen albums (stable album ids + last known names), plus filters: since a date, include videos, include screenshots. New migration through `dotnet ef`. Several devices can share one Photos folder; each device's snapshots stay separate (Source = device), as for files.
2. Album lists: the web form asks the online device for its albums with counts over the hub (the same client-results mechanism and UnifiedPush wake as task 17's browsing; same "allow browsing" switch or a sibling one — decide and say); when offline it shows the last list the device reported (stored on the server, names and counts only).
3. What is stored: originals as they are (no re-encoding): MediaStore files with their bytes, Live/motion photo parts where Android has them, and a JSON sidecar per asset (asset id, original file name, dates taken/modified, size, MIME, dimensions, location if present, albums, favourite). Layout inside the repository snapshot: decide a stable, readable tree (e.g. by year/month or by album, with the asset id in the name to avoid collisions) and document it; it becomes part of the permanent format, so write it down in AGENTS.md as such. Deduplication works across albums (a photo in two albums is stored once) and across renames.
4. Running: the existing BackupJob pipeline with a media source instead of a directory walk; incremental (unchanged assets by id + modified time + size are reused from the parent snapshot without reading them); MediaStore content-trigger jobs start a run when new photos appear (respecting the folder's run conditions); READ_MEDIA_IMAGES/READ_MEDIA_VIDEO (Android 13+), READ_EXTERNAL_STORAGE before, with the partial "selected photos" access of Android 14 handled and explained; ACCESS_MEDIA_LOCATION for location. Deleting a photo on the phone keeps it in older snapshots per retention.
5. Restore: from the app, back into the library (MediaStore insert into the album's relative path), skipping assets that are already there (by id or content), with progress; and `async-cli restore` of a Photos folder writes plain files plus sidecars.
