## The person's goal and the agreed design
Folders sync and back up on the iPhone without the app open, as far as iOS allows, using the same shared decisions Android uses (`BackgroundPlanner`, `RunConditions`, `AgentRuntime.RunAutomaticAsync`, settle time, the reminder). Server and repository formats must not change. Decisions already made: CI produces an unsigned .ipa (sideloaded with SideStore/AltStore); APNs must work once the app is signed with a paid account and degrade cleanly unsigned (no push entitlement → no registration, the app relies on scheduled refresh, reminders and opening the app, as "Working without push" describes).

## Scope
1. **Who schedules:** as on Android, the agent stops running folders on its own interval/at start on iOS (`RunOnInterval = false`, `RunAtStart = false`); it still runs on requests, hub events while connected, reconnects and the app coming to the front (task 21's foreground trigger). Remove task 21's desktop-style foreground scheduling where it conflicts.
2. **BGTaskScheduler:** a `BGAppRefreshTask` (short runs: download folders, small changes, wake handling) and a `BGProcessingTask` (longer runs, `RequiresNetworkConnectivity`, `RequiresExternalPower` when the folders' conditions ask for charging) registered at launch (`BGTaskSchedulerPermittedIdentifiers`, `UIBackgroundModes` fetch + processing), scheduled from `BackgroundPlanner`'s plan (earliest begin = the shortest due folder interval, with iOS's own limits documented), re-submitted after every run and on folder-list changes (not before the first folder list arrived, as on Android). The expiration handler cancels runs cleanly (`SyncAgent.CancelRuns`, *Deferred*, not a failure) and the task completes with success/failure correctly. Applied state kept in the store (like `android-background.json`).
3. **Run conditions** on iOS: Wi-Fi only/unmetered (NWPathMonitor: `isExpensive`/`isConstrained`), charging and battery not low (UIDevice battery state/level, Low Power Mode), wired into `RunConditions` so `FolderStatusDto.Conditions` and the apps show them as on Android; deferred runs end *Deferred*.
4. **Transfers that outlive a run:** use `beginBackgroundTask` around runs started in the foreground so leaving the app does not cut them; resumable uploads/downloads ("Large files") continue at the next run. Evaluate a background `NSURLSession` for large transfers; implement it only if it fits the existing `AsyncApiClient`/gateway transfer code without changing the server protocol, otherwise document why not and what would be needed.
5. **Reminder:** the local "<folder>: nothing synced/backed up for N days" notification (UNUserNotificationCenter, scheduled for N days after the last successful run, replaced by every successful run; same setting and default as Android, 0 = off), asking for notification permission at a sensible moment.
6. **"Back up now" App Intent / shortcut:** an App Intent (iOS 16+) or the closest thing that works from .NET (e.g. a `UIApplicationShortcutItem` home-screen quick action plus an `NSUserActivity`/Siri shortcut) that runs every folder now; pick what is buildable with net10.0-ios and document it.
7. **APNs, ready for signing:** the app registers for remote notifications only when the push entitlement is present (signed builds; the unsigned .ipa has none and must not fail or nag), sends the token to the server through the existing device push registration (`PUT /api/sync/push`, a new `Apns` type in Contracts if needed — additive, no change to existing shapes), and handles a silent push by running `BackgroundPlanner.FoldersToWake` within iOS's 30 s, and the overdue alert via its `loc-key`. On the server, implement **APNs in `Push__Mode=Direct`** (token-based auth with the `.p8` key, Key ID, Team ID, bundle id; HTTP/2 to api.push.apple.com / sandbox), unit-tested against a fake handler; `Relay` stays as it is (the hosted relay needs the person's hosting; mention it in the report). Add the `aps-environment` entitlement and the push step to the signed build path only (the signing steps stay skipped without secrets).
8. **Shared code and tests on Linux:** whatever decides schedules, conditions, reminders and wake handling lives in plain C# (ASync.Client.Core or the iOS head's `Shared/`, linked into ASync.App.Tests as task 21 does) and is unit-tested with concrete checks: the plan → BGTask requests mapping (earliest begin, power/network requirements), expiration → *Deferred* and success reporting, condition mapping (expensive/constrained network, low power, battery), reminder rescheduling on success, the push registration only with the entitlement, APNs request building (JWT claims, headers `apns-push-type`, `apns-priority`, topic) and its error handling (410 unregistered drops the token). Both test projects pass.
