Goal of this task: an Android app that enrolls, shows and syncs folders in the foreground. Background scheduling, UnifiedPush, photos/contacts/calendars are later tasks.

1. `src/ASync.App.Android` (net10.0-android, Avalonia Android head) reusing `src/ASync.App` views and view models. On Android there is no separate agent process: run the agent in-process behind the same interface the desktop app uses for the control channel (an in-process implementation of the client interface), so the shared view models don't change. Keep it ready for a foreground service / WorkManager host in the next task.
2. Device identity: an ECDSA P-256 key generated in the Android Keystore (non-exportable, StrongBox when available, fallback to TEE), signing the device challenge exactly as AGENTS.md "Device provisioning" specifies (IEEE P1363 signature format — convert from DER if the Keystore returns DER). The rest of the identity and unlocked E2E keys stored encrypted with a Keystore AES key. Verify against the real server.
3. Enrollment: server address + code, a pasted or opened `async://pair?s=...&c=...` link (register the `async://` scheme as an intent filter), and scanning the QR code from the web UI's Add device (camera; use a library that needs no Google Play services, e.g. ZXing). Device-code flow too.
4. Folders on Android: local paths are content URIs from the Storage Access Framework (ACTION_OPEN_DOCUMENT_TREE with persisted permissions), not file paths. Introduce an abstraction for the device side's local file tree (list, stat, read, write, delete, move, mtime) used by FolderSyncer and BackupRunner's source, with the existing file-system implementation for desktop/CLI and a SAF (DocumentsContract) implementation for Android. Keep the engine format unchanged. Backup, Mirror and TwoWay must work on SAF trees; note SAF limits (mtime set may be unsupported — handle it).
5. Foreground sync works: sync now, pause/resume, choose folder, live progress, unlock E2E. Android back button and small screens behave.
6. Build: APK (and AAB if cheap) from `scripts/package.sh` or a new script; CI job on ubuntu that builds the APK on pull requests and attaches it to the tag's draft release (extend the release job). Validate the workflow with actionlint.
7. Tests: unit tests for the local file tree abstraction (both implementations' shared contract; the SAF one tested on the emulator), the in-process client, the Keystore signature format conversion. An emulator smoke test (scripts/smoke-android.sh): install the APK, enroll by code against the docker-compose server, attach a TwoWay folder in the web UI, pick a SAF folder (drive the picker with adb/uiautomator, or pre-grant via a test-only path — say which), sync both ways, back up a Backup folder and restore check via async-cli.
