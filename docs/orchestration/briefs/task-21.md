## The person's goal and the agreed design
An iOS app, built only on GitHub macOS runners (there is no Mac; the repo is public, `gh` is authenticated here). Decisions already made by the person:
- **Run the macOS jobs as rarely as possible.** Not on every push of `task/**`, no schedules. On `main` merges only when iOS-relevant files changed (path filters), with a concurrency group that cancels superseded runs. Develop and unit-test everything you can on Linux first (shared code in ASync.App / ASync.Client.Core / tests), then trigger the iOS workflow only when the iOS part is ready to verify, and batch fixes before re-running.
- **Agents may not use workflow_dispatch**, so this task designs how a worker triggers the iOS workflow when the iOS part is ready. Proposal to evaluate (pick what is best, document it in AGENTS.md "Packaging and CI" and explain the choice in your report): a dedicated branch pattern such as `ios-ci/**` that the worker pushes (e.g. `git push origin HEAD:ios-ci/21`) only when it wants a run, deleted afterwards; plus `push` to `main` with `paths:` filters; plus version tags (build the unsigned .ipa and attach it to the GitHub Release without making the desktop/Android release wait on macOS if that is cleaner — decide and document). `workflow_dispatch` may stay in the file for a person. Pull requests: path-filtered at most.
- **Signing:** CI always produces an **unsigned .ipa** (for sideloading with SideStore/AltStore) as an artifact. A signing + TestFlight step is written but skipped until certificate secrets exist (`HAS_*` job variables as the other jobs do, since `if:` cannot read secrets). Push (APNs) and the File Provider extension (later tasks) must work once signed and degrade cleanly unsigned; keep the project structure ready for an app extension and an app group.
- **CI server exception:** the iOS simulator test may run the ASync server natively on the macOS runner with PostgreSQL from Homebrew. This is a CI-only exception to CLAUDE.md rule 5; locally the server stays Docker-only.
- **Server and repository formats must not change for iOS.** Reuse the Android-era interfaces and patterns (IPlatformServices, IDeviceKeyStore, ISecretProtector, local tree factories, InProcessAgentConnector/AgentRuntime in-process, the shared view models, EnrollViewModel, DeviceBrowser scopes, adding folders from the app). Later tasks will reuse IMediaLibrary/MediaTree, IContactsSource/ICalendarSource, BackgroundPlanner and run conditions; don't build those parts now, but don't block them.

## Scope
1. **`src/ASync.App.iOS`** (net10.0-ios, Avalonia.iOS head of the shared `ASync.App`, same app id family as Android: `ua.pp.chds.async`, iOS 15+ unless you find a good reason otherwise). Like the Android head, keep it out of `ASync.slnx` (it cannot build on Linux) and give it its own build script (e.g. `scripts/package-ios.sh`). The agent runs in the app's process like `AndroidAgent` (no control socket).
2. **Device identity:** an `IDeviceKeyStore` with an EC P-256 key in the **Secure Enclave** (via Security framework, non-exportable; Keychain-only software fallback for the simulator where the Secure Enclave is missing), signatures converted to IEEE P1363 (reuse `EcdsaSignatures.DerToP1363`); an `ISecretProtector` that seals the store's files with a Keychain-held AES-GCM key (accessibility AfterFirstUnlockThisDeviceOnly so later background work can read it), as `KeystoreSecretProtector` does on Android. Sign-out deletes the keys; a failed enrollment deletes the key it made.
3. **Enrollment:** server + code, pasted and opened `async://pair` links (URL scheme), QR scanning with the camera (AVFoundation metadata output; no third-party SDKs), device-code flow; `OffersWebUi` false as on Android; plain http servers allowed (ATS exception documented).
4. **Folders:** list and sync in the foreground (the shared views), *Sync now*, adding folders from the app (task 18 design), end-to-end setup/unlock as on Android. Local folders: the app's own Documents folder (exposed in the Files app with `UIFileSharingEnabled`/`LSSupportsOpeningDocumentsInPlace`) and folders the person picks with the document picker, kept through **security-scoped bookmarks** (an iOS local-tree factory resolving `bookmark:` paths, start/stop accessing, stale-bookmark refresh, a "Choose the folder again" failure like SAF's), with `DisplayPath` showing a readable name. Device-folder browsing from the web (task 17) lists what the app can reach.
5. **CI: `.github/workflows/ios.yml`** on a `macos-15` (or newer pinned) runner, triggered as designed above, with a concurrency group: restore the iOS workload, build for the simulator, run the unit tests that matter, run a **simulator smoke test** (the server built and run natively with Homebrew PostgreSQL, the app installed in a booted simulator, enrolled with a code, a folder synced; use `xcrun simctl` and whatever automation works without a paid account), take **screenshots** (`xcrun simctl io booted screenshot`), upload them, the unsigned .ipa and logs as artifacts. The signing/TestFlight step is present and skipped without secrets. Validate with `actionlint` (+ shellcheck) locally. Don't make `docker-publish.yml` slower; if the Release should carry the .ipa, document how.
6. **Run it**: when the iOS part is ready, trigger the workflow your chosen way, watch it with `gh run watch` / `gh run view --log-failed`, download artifacts with `gh run download`, fix in batches, and re-run as few times as you can. Clean up any trigger branches you pushed.
7. **Tests** (on Linux, in ASync.App.Tests / ASync.Tests where the logic lives): the bookmark local tree's path handling and failure messages (behind an interface you can fake), the store sealing format round trip and reading older formats, DER→P1363 use, the enrollment link handling on iOS, and that nothing in the shared view models regresses (`dotnet test` for both test projects passes).
8. **Docs:** AGENTS.md: a new "iOS app (task 21)" section (structure, identity, folders, what's not yet there and which task brings it) and the CI design in "Packaging and CI"; README.md: how to install the unsigned .ipa with SideStore/AltStore and what works; RELEASE_NOTES.md bullet under v0.1.6.
