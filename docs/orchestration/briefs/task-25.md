## The person's goal and the agreed design
The person's ASync folders appear in the iOS Files app (and every document picker) as a location "ASync", with files fetched on demand, as the Android documents provider does since task M4-3: Mirror/TwoWay folders served through the storage gateway (TwoWay writable, Mirror read-only), Backup folders as read-only snapshots. The extension reuses the BCL-only `ASync.Client.Core/Documents/` (`DocumentId`, `DocumentCatalog`, the range readers, the cache) and talks to the server as the device itself (no new endpoint, credential or server check). **Server, Contracts and repository formats must not change.** Decided with the person: CI always produces an unsigned .ipa for sideloading (SideStore/AltStore); the File Provider must work once the app is signed with a paid account and **degrade cleanly** unsigned (the app runs as before, says why the Files location is missing, nothing crashes).

## Scope
1. **The extension project** (e.g. `src/ASync.App.iOS.FileProvider`, net10.0-ios, `IsAppExtension`, `NSExtensionPointIdentifier` `com.apple.fileprovider-nonui`, principal class an `NSFileProviderReplicatedExtension`), embedded in the app (`PlugIns/`), bundle id `ua.pp.chds.async.fileprovider`, built by `scripts/package-ios.sh` and `scripts/check-ios.sh`. Mind the extension's memory limit: no Avalonia in the extension, trimmed/AOT settings that keep it small, measure its footprint in CI and document it.
2. **Sharing between app and extension:** an app group (`group.ua.pp.chds.async`) container for the store the extension needs (identity, folder list snapshot, the cache) and a shared Keychain access group for the Secure Enclave key and the sealing key (task 21's `SecureEnclaveDeviceKeys` / `SealedStoreProtector`), with a migration of task 21's existing store into the group container when the group is available and staying where it is when it is not (unsigned/sideloaded without the entitlement). Decide which process signs device challenges (the extension signing with the shared key, or asking the app) and document why. The domain (`NSFileProviderDomain`, one per enrolled account, "ASync — <server host>") is added by the app after enrollment and removed on sign-out/revocation, with a clear text in the listing when revoked.
3. **Enumeration and contents** from `DocumentCatalog`: item identifiers from `DocumentId` (root/working set mapped), enumerators for directories with paging and sync anchors, `fetchContents` streaming into the system-provided URL with progress (large files through the range readers, never whole in memory), errors mapped to `NSFileProviderError` (not authenticated, server unreachable, no such item), `.async` hidden, Backup snapshots read-only.
4. **Writes (TwoWay only):** `createItem`, `modifyItem` (contents, rename, move within a folder), `deleteItem` via `DocumentCatalog.WriteAsync` and the existing plain store operations, exactly as the Android provider (versions kept, no lease, conflicts as there); Mirror and Backup items refuse with the right capabilities so the Files app greys out the actions.
5. **Change signalling:** the working set and directory enumerators signalled (`NSFileProviderManager.signalEnumerator`) when the app sees `folder.changed` over the hub, after its own syncs touch a folder, and on a silent push (task 22) when signed; materialised items evicted sensibly; document what iOS does without push (the Files app refreshes on open).
6. **The open item from task 21:** reading folders the person picked that live in other providers (iCloud Drive files not downloaded, other file providers' placeholders) through `NSFileCoordinator` coordinated reads in the bookmark tree, so placeholders are downloaded instead of failing; plain C# decisions unit-tested.
7. **Degrading cleanly:** without the app-group/keychain-group entitlements (unsigned .ipa, or a sideloader that strips them), the app detects it at start, does not register a domain, keeps its store where it was, and shows one short line in Settings ("The Files app location needs a signed build"); the signed path in `ios.yml`/`package-ios.sh --signed` adds the entitlements and provisioning for both bundle ids (the signing steps stay skipped without secrets). Check what the simulator honours with ad-hoc signing and use that for the CI test.
8. **Tests on Linux:** identifier mapping both ways (root, working set, f/, b/, s/ ids, refusals), capabilities per folder kind, enumeration paging/anchors, write mapping (create/modify/rename/move/delete → catalog calls; Mirror/Backup refused), error mapping, the store migration into the group container and its fallback, entitlement detection, `NSFileCoordinator` decision logic. Both test projects pass.
