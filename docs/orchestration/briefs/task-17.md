1. Protocol: the server asks an online device to list a directory over the existing SignalR hub (SignalR client results, `ISingleClientProxy.InvokeAsync<T>`, or request/response with a correlation id: say which and why), with a timeout (e.g. 10 s) and a size limit (e.g. 2000 entries, then "and N more"). Answer: the directory's entries (directories first; files optional, greyed, with size, so the person recognises the place), its canonical path, its parent, and the device's starting points (home, Desktop/Documents/Pictures, drives on Windows, mounted volumes on Linux/macOS, internal storage/SD cards/Download on Android). Optional: create a subfolder from the picker (the device creates it).
2. Server: a people's endpoint (Roles.Users) `GET /api/devices/{id}/browse?path=` (and POST .../browse/mkdir if you do 1's option), owner only, active (not revoked) devices only, 409 with a clear message when the device is offline, has browsing turned off, or (Android) has no All files access (then: "choose the folder in the app, or turn on All files access"). Never through device tokens. Rate-limit it. Nothing is stored.
3. Device side: CLI agent (`async-cli run`), the desktop agent service, and the Android in-process agent answer. A per-device setting "Allow browsing folders from the web" (default on; CLI: a flag/env var, desktop and Android: in Settings), reported to the server so the web UI can say why it's unavailable. Respect the same exclusions as task 16 on Android (Android/data, obb). Symlinks: shown, not followed past the listing; unreadable directories shown as such, not an error for the whole listing.
4. Web UI: a *Browse…* button next to the local path in the device-folder form (FolderDeviceForm) opening a folder picker: breadcrumbs, starting points, directories, back/up, select. Typing the path stays possible (offline devices). Follow "Web UI style"; must fit 390 px. The Devices page shows whether browsing is available per device.
5. Tests: unit tests for the device-side listing (limits, exclusions, unreadable entries, symlinks, Windows-style paths in a pure helper) and the server endpoint (owner check, offline, timeout, turned off, revoked) with fakes; API-level role-separation tests pick up the new endpoint; e2e-sync.cs: browse a running CLI agent's directory through the API and pick a path, then sync to it; the Android smoke test: browse the emulator's storage root from the API with All files access on, and get the clear 409 with it off. Run ASync.Tests (test stack up), ASync.App.Tests, scripts/e2e-sync.sh and the Android smoke test; make them pass.
